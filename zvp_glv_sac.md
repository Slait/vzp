# Боевой скрипт для атаки ZVP-GLV на Страуса-трюк Шамира

## Описание

Данный скрипт реализует атаку **ZVP-GLV на Страуса-трюк Шамира** из раздела 4.3 научной работы "Decompose and conquer: ZVP attacks on GLV curves". Атака нацелена на восстановление верхних битов секретного скаляра при использовании GLV-декомпозиции на кривой secp256k1.

### Принцип работы

Атака использует:
- **Zero-Value Point (ZVP)** атаку для обнаружения нулевых промежуточных значений
- **GLV-декомпозицию** скаляра `d = d₀ + d₁·λ (mod n)`
- **GLV-SAC кодирование** для представления скаляров
- **Dependent Coordinates Problem (DCP)** solver для поиска специальных точек

Алгоритм итеративно восстанавливает верхние биты обоих скаляров `d₀` и `d₁` одновременно, что позволяет восстановить в два раза больше битов по сравнению с классической ZVP атакой.

## Использование

### Базовый синтаксис
```bash
sage -python zvp_glv_sac.py --pubkey <HEX_PUBKEY> [OPTIONS]
```

**Важно**: Скрипт требует SageMath для работы. Если SageMath не установлен, используйте альтернативный запуск:
```bash
# Если SageMath установлен глобально
sage -python zvp_glv_sac.py --pubkey <HEX_PUBKEY> [OPTIONS]

# Если используете conda/pip установку Sage
python -m sage zvp_glv_sac.py --pubkey <HEX_PUBKEY> [OPTIONS]
```

### Обязательные параметры

#### `--pubkey` (обязательно)
Публичный ключ в hex формате (128 hex символов)
- **Формат**: Начинается с `04` (несжатый формат)
- **Длина**: Ровно 130 символов (04 + 64 + 64 hex символа)
- **Содержимое**: `04` + X-координата (64 hex) + Y-координата (64 hex)

### Опциональные параметры

#### `--bits` (по умолчанию: 4)
Количество целевых бит для атаки
- **Диапазон**: 2-32
- **Рекомендация**: 
  - Для тестирования: 4-6 битов
  - Для серьезных атак: 6-10 битов
  - Более 10 битов: требует значительного времени

#### `--save`
Сохранить результаты в JSON файл
- **Формат**: Имя файла без расширения
- **Расположение**: Автоматически сохраняется в `attack/results/`
- **Имя файла**: `<filename>_YYYYMMDD_HHMMSS.json`

#### `--verbose`
Подробный вывод процесса атаки
- Показывает количество предположений на каждой итерации
- Полезно для отладки и понимания процесса

### Ключевые метрики

#### Восстановлено битов
- **Формула**: `2 × target_bits - log₂(количество_кандидатов)`
- **Интерпретация**: Фактическое количество информации, полученной об исходном скаляре
- **Максимум**: `2 × target_bits` (если найден единственный кандидат)

#### Количество кандидатов
- **Меньше 10**: Отличный результат, все кандидаты показываются
- **10-100**: Хороший результат
- **Больше 100**: Результат требует дополнительного анализа

#### Кандидаты скаляров
- **Формат**: GLV-SAC представление в виде `[d₀, d₁]`
- **Значения**: `{-1, 0, 1}` для каждого бита
- **Порядок**: От старших битов к младшим

## Технические детали

### Используемые алгоритмы
- **Страуса-трюк Шамира** (Algorithm 3 из статьи)
- **GLV-SAC кодирование** для представления скаляров
- **Projective:madd-2015-rcb** координатная система (лучшие результаты)

### DCP полиномы
Скрипт использует следующие промежуточные (IV) полиномы для secp256k1:
- `f1`: X₁ + X₂ 
- `f8`: -(X₁³)X₂³ - X₁³B - X₂³B + 8B², Y₁Y₂ - 3B
- `f9`: -(X₁³)X₂³ - X₁³B - X₂³B + 8B², Y₁Y₂ + 3B
- `f10`: -(X₁²)X₂² + X₁B + X₂B, X₂Y₁ + X₁Y₂
- `f11`: X₁³X₂³ - X₁²X₂² + X₁³B + X₂³B + B², X₁X₂ + Y₁Y₂

### Временная сложность
- **4 бита**: ~10-30 секунд
- **6 битов**: ~1-5 минут  
- **8 битов**: ~10-60 минут
- **10+ битов**: несколько часов

## Возможные ошибки и решения

### Ошибка: "Публичный ключ должен начинаться с '04'"
**Причина**: Неверный формат публичного ключа
**Решение**: Используйте несжатый формат, начинающийся с `04`

### Ошибка: "Точка не лежит на кривой secp256k1"
**Причина**: Неверные координаты или поврежденный ключ
**Решение**: Проверьте правильность публичного ключа

### Ошибка: "No module named 'sage'"
**Причина**: SageMath не установлен или не в PATH
**Решение**: Установите SageMath или запустите через Sage

### Низкое количество восстановленных битов
**Причина**: DCP проблемы не имеют решений для данного ключа
**Решение**: 
- Попробуйте другое количество целевых битов
- Это нормальное поведение для реальных ключей
