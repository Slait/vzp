# ZVP-GLV Attack on Straus-Shamir Trick

Данный документ описывает использование скрипта `attack_zvp_glv_sac.py` для проведения ZVP-GLV атаки на алгоритм Straus-Shamir trick с GLV-SAC представлением на кривой secp256k1.

## Описание атаки

ZVP-GLV атака основана на исследовании "Decompose and conquer: ZVP attacks on GLV curves" (раздел 4.3). Атака использует:

- **Zero-Value Point (ZVP)** атаку для выявления промежуточных нулевых значений
- **GLV декомпозицию** для ускорения мультискалярного умножения
- **Straus-Shamir trick** с GLV-SAC представлением как целевой алгоритм

### Принцип работы

1. Приватный ключ `d` декомпозируется как `d = d₀ + d₁λ (mod n)`
2. Атака восстанавливает верхние биты GLV-SAC представления `(d₀, d₁)`
3. Используются полиномы промежуточных значений из EFD (Explicit Formulas Database)
4. Атака может восстановить в два раза больше битов по сравнению с классической ZVP атакой

## Использование скрипта

### Основной синтаксис
```bash
python attack_zvp_glv_sac.py --pubkey <HEX_PUBKEY> [OPTIONS]
```

### Параметры

#### Обязательные параметры
- `--pubkey` - Публичный ключ в несжатом формате (128 hex символов)
  - Формат: `04<x_coordinate><y_coordinate>`
  - Пример: `04ceb6cbbcdbdf5ef7150682150f4ce2c6f4807b349827dcdbdd1f2efa885a26302b195386bea3f5f002dc033b92cfc2c9e71b586302b09cfe535e1ff290b1b5ac`

#### Опциональные параметры
- `--bits` - Количество целевых битов для восстановления (2-32, по умолчанию: 4)
- `--save` - Сохранить результаты в JSON файл
- `--verbose`, `-v` - Подробный вывод

## Интерпретация результатов

### Выходная информация
Скрипт выводит следующую информацию:

1. **Настройка параметров**
   - Количество целевых битов
   - Используемый набор регистров (формулы EFD)
   - Количество полиномов промежуточных значений

2. **Информация о публичном ключе**
   - Координаты точки (x, y)
   - Проверка принадлежности кривой secp256k1

3. **Результаты атаки**
   - Время выполнения
   - Количество восстановленных битов
   - Количество кандидатов (пар k₀, k₁)

## Настройка параметров атаки

### Выбор количества битов
- **2-4 бита**: Быстро (секунды), низкая точность
- **5-8 битов**: Умеренно (минуты), хорошая точность
- **9-16 битов**: Медленно (часы), высокая точность
- **17+ битов**: Очень медленно (дни), максимальная точность

### Наборы регистров EFD
Скрипт автоматически выбирает лучший набор формул:

1. **projective:madd-2015-rcb** (70% успеха, 5 полиномов)
2. **modified:mmadd-2009-bl** (66% успеха, 3 полинома)
3. **projective:add-2002-bj** (27% успеха, 2 полинома)
4. **jacobian:add-1998-cmo** (16% успеха, 1 полином)

## Производительность

### Временные характеристики (на стандартном ПК)
- **4 бита**: ~10-60 секунд
- **6 битов**: ~2-10 минут
- **8 битов**: ~10-60 минут
- **10 битов**: ~1-5 часов

### Факторы, влияющие на производительность
1. Количество целевых битов
2. Количество полиномов промежуточных значений
3. Коэффициент успеха DCP решателя
4. Вычислительная мощность системы

### Технические ограничения
- Работает только с кривой secp256k1
- Требует компиляции PARI инструментов

### Теоретические ограничения
- Не гарантирует 100% успех для всех ключей

### Практические соображения
- Для реальных атак требуется физический доступ к устройству

## Расширенные возможности

### Добавление новых формул
Для добавления новых EFD формул:
1. Добавьте полиномы в `utils.py::get_secp256k1_polynomials()`
2. Зарегистрируйте формулу в `utils.py::load_efd_secp256k1_registers()`
3. Протестируйте с помощью `tests.py`

### Адаптация для других кривых
Для адаптации под другие GLV кривые:
1. Измените параметры кривой в `glv.py`
2. Адаптируйте полиномы под новую кривую
3. Обновите DCP решатель в `pari_tools/`

## Устранение неполадок

### Типичные ошибки

#### "Point is not on curve"
```bash
Error: Point (0x..., 0x...) does not lie on the curve
```
**Решение**: Проверьте корректность публичного ключа

#### "PARI tools not compiled"
```bash
ImportError: cannot import name 'dcpsolver_pari'
```
**Решение**: 
```bash
cd attack/pari_tools
make clean
make
```

#### "No candidates found"
```bash
Attack completed but no candidates found
```
**Решение**: 
- Увеличьте количество битов
- Попробуйте другую формулу EFD
- Проверьте корректность входных данных

### Диагностика производительности
Используйте `--verbose` для подробной диагностики:
```bash
python attack_zvp_glv_sac.py --pubkey <PUBKEY> --bits 4 --verbose
```

### Логирование ошибок
Ошибки автоматически записываются в `error.log`
