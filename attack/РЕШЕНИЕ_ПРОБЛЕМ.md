# Решение проблем с ZVP-GLV атаками

## 🔥 Проблемы которые вы испытываете:

### 1. **Переполнение стека PARI**
```
***   the PARI stack overflows !
current stack size: 16000000000 (15258.789 Mbytes)
```

### 2. **Ошибка JSON сериализации**
```
TypeError: Object of type Integer is not JSON serializable
```

## ✅ БЫСТРОЕ РЕШЕНИЕ

### Шаг 1: Настройка PARI (ОБЯЗАТЕЛЬНО)
```bash
cd attack
sage setup_pari.py
```

Этот скрипт:
- Создаст файл `~/.gprc` с увеличенным размером стека до 64GB
- Настроит переменные окружения
- Протестирует настройки

### Шаг 2: Использование исправленного файла
Вместо `experiments.py` используйте:
```bash
sage fix_experiments.py
```

Или интерактивный интерфейс:
```bash
sage run.py
```

## 🔧 Детальное решение

### Для переполнения стека PARI:

1. **Создайте файл ~/.gprc** с содержимым:
```
parisizemax = 64000000000   /* 64GB максимум */
parisize = 32000000000      /* 32GB начальный размер */
stackwarn = 0               /* Отключить предупреждения */
```

2. **Перезапустите Sage**:
```bash
sage --reset
```

3. **Уменьшите параметры атаки**:
- `target_bits = 3` или `4` (вместо больших значений)
- `n_exp = 1` (вместо 10+)

### Для ошибок JSON:

Используйте `fix_experiments.py` который:
- Автоматически конвертирует объекты Sage в обычные Python типы
- Безопасно сохраняет результаты в JSON
- Имеет защиту от ошибок

## 📋 Рекомендуемый порядок действий:

1. **Настройка системы**:
```bash
cd attack

```

2. **Компиляция PARI инструментов** (если еще не сделано):
```bash
cd pari_tools
make

```

3. **Тестовый запуск**:
```bash
sage fix_experiments.py
# Выберите "1" для DCP атаки
```

4. **Интерактивный запуск**:
```bash
sage run.py
# Следуйте инструкциям в меню
```

## ⚙️ Альтернативные настройки

### Если у вас мало RAM (< 32GB):

В файле `~/.gprc` используйте меньшие значения:
```
parisizemax = 16000000000   /* 16GB максимум */
parisize = 8000000000       /* 8GB начальный размер */
```

### Для слабых машин:

В атаках используйте:
- `target_bits = 3`
- `n_exp = 1`
- `window_size = 3` (для interleaving)

## 🚨 Если проблемы продолжаются:

1. **Очистите кэш Sage**:
```bash
rm -rf ~/.sage/cache
sage --reset
```

2. **Проверьте доступную память**:
```bash
free -h
```

3. **Используйте меньшие параметры**:
```python
# В fix_experiments.py или run.py
zvpparams.target_bits = 3  # Начните с 3 бит
```

4. **Альтернативный способ**:
```bash
# Запуск с ограничением памяти
ulimit -v 32000000  # 32GB виртуальной памяти
sage fix_experiments.py
```
