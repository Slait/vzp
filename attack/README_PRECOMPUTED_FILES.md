# Предвычисленные файлы DCP для ZVP-GLV атаки

## Обзор

Файлы `interleaving_secp256k1_remapped_*.json` содержат предвычисленные решения Dependent Coordinates Problem (DCP) для различных размеров окон w-NAF. Эти файлы критически важны для эффективности атаки ZVP-GLV на window interleaving.

## Структура файлов

### Имена файлов
- `interleaving_secp256k1_remapped_3.json` - для window size = 3
- `interleaving_secp256k1_remapped_4.json` - для window size = 4  
- `interleaving_secp256k1_remapped_5.json` - для window size = 5

### Формат данных

Каждый файл содержит массив объектов с полями:

```json
[
  {
    "register": [["polynomial_x", "polynomial_y"]],
    "points": [
      [[point_x, point_y], [[g0_1, g1_1], [g0_2, g1_2], ...]]
    ]
  }
]
```

#### Поля:
- **register**: Полиномы для обнаружения нулей (формулы регистров)
- **points**: Массив точек кривой и связанных с ними скалярных пар
  - Каждый элемент: `[[x, y], scalar_pairs]`
  - `x, y`: Координаты точки на secp256k1
  - `scalar_pairs`: Пары `[g0, g1]`, которые вызывают обнуление для данной точки

## Назначение файлов

### 1. Ускорение предвычислений
Вместо решения DCP "на лету" для каждой пары (g0, g1), атака загружает предвычисленные решения.

### 2. Mapping точек к скалярам
Файлы содержат обратное отображение: для каждой точки P указаны все пары (g0, g1), которые могут вызвать обнуление в этой точке.

### 3. Оптимизация oracle запросов
Oracle может эффективно проверить, вызывает ли данная точка обнуление, используя предвычисленные данные.

## Как создаются файлы

### Скрипт генерации: `zvp_glv_inter_easy_prec.py`

```python
def dcp_points_remapping(zvpparams, w):
    # 1. Загружает результаты DCP экспериментов
    # 2. Для каждой найденной точки
    # 3. Тестирует все возможные пары (g0, g1) для данного размера окна
    # 4. Сохраняет mapping: точка -> список пар (g0, g1)
```

### Процесс генерации:
1. **DCP solving**: Решение полиномиальных систем для нахождения "особых" точек
2. **Scalar enumeration**: Для каждой точки проверка всех w-NAF значений
3. **Zero detection**: Определение, какие пары (g0, g1) вызывают обнуления
4. **Mapping creation**: Создание обратного отображения для быстрого поиска

    if os.path.exists(remapped_file):

## Производительность

### Без предвычисленных файлов:
- **Время**: ~10-30 секунд на размер окна
- **Память**: Минимальная
- **CPU**: Интенсивные вычисления DCP

- **Время**: ~0.002 секунды загрузки
- **Память**: ~10-200 MB (зависит от размера окна)

## Математическая основа

### DCP (Dependent Coordinates Problem):
Найти точки P такие, что для некоторых скаляров g0, g1:
```
register_polynomial(g0*P, g1*λ*P) = 0
```

### Регистровые полиномы:
Примеры из файлов:
- `"X1 + X2"` - простое сложение координат
- `"-X1^4 + 6*X1^3*X2 - 7*X1^2*X2^2 + ..."` - сложные полиномиальные отношения

### w-NAF значения:
Для размера окна w, возможные значения: `{±1, ±3, ±5, ..., ±(2^(w-1)-1)}`

## Устранение неисправностей

### Файл не найден:
```
Warning: Precomputed file results/interleaving_secp256k1_remapped_5.json not found
Falling back to on-demand DCP solving
```
**Решение**: Проверьте путь и наличие файла в `attack/results/`

### Ошибка загрузки:
```python
# alternative.py автоматически переключается на fallback
self._precompute_dcp_on_demand()
```

### Генерация новых файлов:
Запустите `zvp_glv_inter_easy_prec.py` с нужными параметрами для создания файлов для новых размеров окон.

## Заключение

Предвычисленные файлы DCP являются ключевым компонентом для эффективной работы ZVP-GLV атаки. Они обеспечивают:

1. **Быструю инициализацию** атаки
2. **Эффективные oracle запросы**
3. **Масштабируемость** для больших размеров окон
4. **Воспроизводимость** результатов

Файлы создаются один раз для каждого размера окна и могут использоваться многократно для различных атак на secp256k1.
